# Handbuch für System-Administration & Docker

Dieses Betriebshandbuch dient als zentrales Nachschlagewerk für die Einrichtung, Verwaltung und Fehlerbehebung der Oracle-Datenbank-Umgebung innerhalb von Docker unter macOS. Es trennt administrative System-Befehle strikt von den reinen SQL-Sprachfunktionen.

## 1. Docker und Umgebung zurücksetzen

Typische Befehle zur Fehlerbehebung und Systemwiederherstellung bei der Arbeit mit Oracle im Docker-Container.

> ⚠️ **Achtung:** Durch das Löschen des Containers wird die Datenbank mit allen Inhalten komplett gelöscht! Stell sicher, dass deine Skripte auf GitHub gesichert sind.

Wenn der Container neu gestartet oder mit Verzeichnis-Freigaben (`Volume Mapping`) versehen werden muss:
```bash
# Container stoppen und vollständig löschen
docker stop oracle-free && docker rm oracle-free

# Container neu starten mit Mac-Ordner-Verknüpfung (-v Pfad_Mac:Pfad_Container)
docker run -d --name oracle-free -p 1521:1521 \
  -e ORACLE_PASSWORD=DeinPasswort \
  -v ~/Documents/oracle-sql-lernen/bundesliga-tippspiel/import_ordner:/opt/oracle/oradata/import \
  gvenzl/oracle-free:latest
```

## 2. Benutzer-Administration

Wenn nach einem Docker-Reset der Arbeits-User (`LERNEN`) neu angelegt oder sein Passwort geändert werden muss:
```sql
-- 1. Namensschutz im aktuellen Fenster für Standard-Namen ausschalten
ALTER SESSION SET "_oracle_script"=true;

-- 2. Benutzer neu anlegen mit unbegrenztem Speicherplatz
CREATE USER LERNEN IDENTIFIED BY DeinPasswort QUOTA UNLIMITED ON USERS;

-- 3. Standard-Entwicklerrechte vergeben
GRANT CONNECT, RESOURCE, CREATE VIEW, CREATE JOB TO LERNEN;

-- 4. Passwort eines bestehenden Benutzers nachträglich ändern
ALTER USER LERNEN IDENTIFIED BY NeuesPasswort;
```

## 3. Verzeichnis- und Job-Berechtigungen

Fehler wie `ORA-22285` (Verzeichnis nicht vorhanden) oder `ORA-27486` (Keine Berechtigung für Jobs) lösen:
```sql
-- Verzeichnis-Objekt auf Server-Pfad mappen
CREATE OR REPLACE DIRECTORY bl_import_dir AS '/opt/oracle/oradata/import';

-- Explizite Lese- und Schreibrechte an den Arbeits-User vergeben
GRANT READ, WRITE ON DIRECTORY bl_import_dir TO LERNEN;

-- Berechtigung für den Oracle Scheduler vergeben
GRANT CREATE JOB TO LERNEN;
```

## 4. Identity-Spalten nach TRUNCATE zurücksetzen

Wenn die Tabelle geleert wird, der ID-Zähler aber wieder bei 1 starten soll:
```sql
-- Weg A: Nachträglich den Zähler zurücksetzen
ALTER TABLE tabellen_name MODIFY (id_spalte GENERATED BY DEFAULT AS IDENTITY (START WITH LIMIT VALUE));

-- Weg B: Tabelle leeren und Zähler im selben Schritt zurücksetzen (Empfohlen!)
TRUNCATE TABLE tabellen_name RESTART IDENTITY;
```

## 5. Package and Job Troubleshooting

Befehle zur Fehleranalyse von ungültigen Objekten und zum Beenden von hängenden Hintergrund-Prozessen.

#### 1. Kompilierungsfehler im Package-Body anzeigen
Wenn ein Package den Status `INVALID` hat, zeigt dieser Befehl die exakte Zeile und den Grund des Syntaxfehlers an:
```sql
SELECT line, position, text 
FROM user_errors 
WHERE name = 'BL_IMPORT_PKG' AND type = 'PACKAGE BODY';
```

#### 2. Den Status und nächsten Start von Jobs prüfen
Prüft, ob ein Job aktiv im Hintergrund läuft (`RUNNING`), auf seinen Einsatz wartet (`SCHEDULED`) oder deaktiviert ist:
```sql
SELECT job_name, state, next_run_date 
FROM user_scheduler_jobs;
```

#### 3. Die Fehler-Historie (Logbuch) des Schedulers auslesen
Zeigt an, ob die letzten Hintergrund-Läufe erfolgreich waren (`SUCCEEDED`) oder mit welchen ORA-Fehlern sie abgebrochen sind:
```sql
SELECT log_date, status, error# AS error_code, additional_info 
FROM user_scheduler_job_run_details 
WHERE job_name = 'JOB_BUNDESLIGA_IMPORT'
ORDER BY log_date DESC;
```

#### 4. Einen hängenden Job (Endlosschleife) sofort abbrechen
Falls sich ein Job im Hintergrund aufhängt und die Tabellen blockiert, wird er mit diesem Befehl sofort hart beendet:
```sql
BEGIN
    DBMS_SCHEDULER.STOP_JOB(job_name => 'job_bundesliga_import', force => TRUE);
END;
/
```

#### 5. Datenbank-Blockaden und Sperren lösen (Deadlocks auflösen)
Bricht unvollständige Transaktionen ab und leert den SQL-Zwischenspeicher, um blockierte Tabellen wieder freizugeben:
```sql
ROLLBACK;
ALTER SYSTEM FLUSH SHARED_POOL; -- (Auszuführen als SYSTEM-User)
```
